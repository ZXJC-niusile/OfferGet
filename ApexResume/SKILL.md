# ApexResume（顶峰技术简历锻造与审计系统）

ApexResume 是一套专为**技术人才（尤其是 AI / 大模型 / Agent / 算法 / 高性能计算工程师）**打造的求职交付流水线。
它融汇了技术包装的表达力与严肃的证据链自审机制，支持**三大核心工作模式**、**五阶段响应契约（Phase Response Contract）**、**三层面试防御闭环**，并内嵌了**自动化确定性校验**与**像素级单页自动压页算法**。

---

## 一、 核心红线与设计哲学

> **唯一铁律：“只放大，不虚构。”**  
> 写上去的每一条经历，必须能在技术大厂资深专家面试官的 **3 层深入追问下守住 15 分钟**。守不住的浮夸包装是致命的负资产。

1. **攻守兼备**：
   - **攻（叙事升维）**：挖掘水下冰山，用 Mini-RFC 架构（痛点 $\to$ 演进 $\to$ 链路 $\to$ 指标）叙述方案，施加细节参数威慑。
   - **守（防伪门禁）**：拒绝任何凭空造假，严格执行动词层级约束（支持/协助 < 参与 < 负责 < 推动 < 主导）、数据深度（D0-D4）与成果证据（R0-R3）等级标记、以及底稿沙盒防伪防幻觉校验。
2. **抗同质化（拒绝见光死）**：
   - 告别千篇一律的模板撞车，提供经典科技蓝、硅谷黑白极简、现代藏蓝与 ATS 纯文本四套主题，彻底消除“一看就是套阿酥模板”的面试反感。
3. **确定性交付**：
   - 数学重算、动词层级审计、占位符扫描与底稿沙盒校验交给 Python 代码，排版卡页数交给 AutoFit 引擎，杜绝玄学调试。

## 二、 阶段响应契约 (Phase Response Contract)

为杜绝大模型在缺少事实与证据时凭空编造、一股脑输出未经检验的内容，Agent 与用户交互必须严格遵循**五阶段递进响应契约**：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   ApexResume 阶段响应契约 (Phase Contract)               │
├────────────────────────────────────────────────────────────────────────┤
│ [Phase 1: 事实对齐与 JD 8 维解码]                                       │
│  输入：用户初始素材 + 目标 JD                                          │
│  规范：references/jd-matrix-framework.md                               │
│  产出：8 维细粒度解码卡 + 要求-证据初筛矩阵 + 硬门槛 0/1 物理隔离判定  │
│  门禁：硬门槛通过判定；用户确认重点经历取舍与排序                      │
├───────────────────────────────────┬────────────────────────────────────┤
│ [Phase 2: 原子主张台账与矩阵匹配]                                      │
│  输入：选定的重点经历                                                  │
│  规范：references/claim-ledger-schema.md & evidence-rules.md           │
│  产出：4 维原子拆解 (职责/方法/指标/因果) + 动词与 D/R 定级 + 置信状态机 │
│  门禁：强动词方案决策证据核验；基线与口径一致；用户确认消除真实缺口     │
├───────────────────────────────────┬────────────────────────────────────┤
│ [Phase 3: Mini-RFC 叙事与沙盒门禁]                                     │
│  输入：已验证的原子事实台账                                            │
│  规范：references/methods-11.md & core/audit.py                        │
│  产出：Mini-RFC 高信号文案 + 选定 HTML 主题 + 执行沙盒防幻觉审计       │
│  门禁：python cli.py audit 校验 100% Passed (0 幻觉数字, 0 角色越级)   │
├───────────────────────────────────┬────────────────────────────────────┤
│ [Phase 4: 排版交付与 AutoFit 压页]                                     │
│  输入：审计通过的 HTML                                                 │
│  工具：cli.py autofit & themes/                                        │
│  产出：像素级锁定 1 页 A4 PDF + themes/ats-plain.md 纯文本版           │
│  门禁：单页高度无溢出 (溢出像素 <= 0)                                   │
├───────────────────────────────────┬────────────────────────────────────┤
│ [Phase 5: 直聘触达与猎头 Pitch 交付]                                   │
│  输入：最终简历核心亮点 + 目标 JD 痛点                                 │
│  规范：references/hr-pitch-guide.md                                    │
│  产出：Boss 直聘 80-150 字黄金三段式开场白 + 猎头 Executive Summary     │
│  门禁：完成三层面试防御卡闭环演练，正式发起求职投递                    │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、 面试防御闭环体系 (Interview Defense Closed-Loop)

简历并非一次性的展示卡，而是**技术面试答辩的主场作战地图**。每一个写进简历的核心技术点，必须在台账中绑定 **3 层递进防御纵深**：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        3 层面试防御递进纵深                             │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 1: 5 秒扫视层 (Headline & Keyword Anchors)                       │
│ 目标：施加第一眼威慑，树立“高阶工程专家/主力架构”预设                  │
│ 内容：参数级硬核名词（如 GRPO、Continuous Batching、P99 -50%、82.5%）   │
├────────────────────────────────────────────────────────────────────────┤
│ Layer 2: 2 分钟技术方案答辩层 (Trade-off & Architecture)               │
│ 目标：证明候选人具备系统设计与技术选型权，而非被动执行者               │
│ 追问：“为什么选 A 方案而不选 B 方案？系统的主要瓶颈与 Trade-off 是什么？”│
│ 防御：准备方案对比实验数据、关键参数选型依据（如为什么选 GRPO 舍弃 PPO）│
├────────────────────────────────────────────────────────────────────────┤
│ Layer 3: 15 分钟白板与背调深穿透层 (Whiteboard & Edge-Cases)           │
│ 目标：粉碎所有浮夸包装，检验底层原理、故障边界与代码真实性             │
│ 追问：“如果遇到极端负载/梯度爆炸/显存碎片如何兜底？背调联系主管会穿帮吗？”│
│ 防御：详述失败尝试、降级容灾方案、白板推演关键计算公式、可复现代码锚点 │
└────────────────────────────────────────────────────────────────────────┘
```

### 双闸门防伪门禁 (Dual Gate Enforcement)
- **闸门 A（确定性脚本硬校验）**：
  - 运行 `python cli.py audit --claims claims.json --html resume.html --source draft.txt`
  - 脚本自动重算分子分母与百分点、执行动词五级阶梯校验、扫描角色越级、排查时态冲突与 `.todo` 占位符、拦截底稿沙盒幻觉数字。
  - **脚本校验未通过，绝对不得交付最终简历！**
- **闸门 B（模拟面试追问答辩）**：
  - Agent 模拟刁钻技术专家对成稿发起追问：
    1. *“提升约 25%+ 的 Baseline 是什么？是在什么机器上测的？”*
    2. *“简历里的 Short CoT 截断，能脱稿用两分钟给我讲清楚为什么不影响准确率吗？”*
    3. *“声称从 0 到 1 端到端，背调如果联系你们组 Leader 会穿帮吗？”*
  - 用户确认回答不上来的条目，**必须当场降级或修改**。

## 四、 三大工作模式 (Operating Modes)

根据用户诉求，Agent 应主动引导用户选择以下三种模式之一：

```
               ┌───────────────────────────────┐
               │    用户输入初始经历 / 简历片段   │
               └───────────────┬───────────────┘
                               │
       ┌───────────────────────┼───────────────────────┐
       ▼                       ▼                       ▼
【模式 A: 极速锻造】    【模式 B: 深度重构】     【模式 C: 独立审计】
 (Quick Forge)           (Pro Forge - 标杆推荐)   (Self Audit)
 适合：已有现成素材     适合：冲刺一线顶尖高薪   适合：求职前自审/背景尽调
 快速提炼高密度文案     五阶段响应契约全闭环     拆解 4 维原子 Claim
 套用选定工业级主题     挖料 + 答辩 + 压页       沙盒对齐 + 夸大模式排查
 一键导出 A4 单页 PDF   工业级全闭环交付         出具红蓝对抗背调报告
```

## 六、 命令行工具清单 (CLI Reference)
