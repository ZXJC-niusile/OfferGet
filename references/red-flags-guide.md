# 技术岗位红旗与陷阱清单 (Red Flags Guide)

> **OfferGet 核心防线**：拿到 Offer 只是第一步，避开“深坑团队”才是职业生涯长期增值的关键。
> 本指南梳理了技术研发（尤其是 AI/算法/大模型）岗位的 **5 大致命红旗**，并提供独家设计的 **15 道反问求证探针问题**，助你在面试中反向背调用人团队。

---

## 5 大类致命技术红旗 (Fatal Red Flags)

```
┌──────────────────────────────────────────────────────────────────┐
│ 1. 算力与基建欺诈 (Compute Trap)   ── 宣称做基座，实际只有几张消费卡 │
│ 2. 伪 AI 与战略摇摆 (Strategy Trap) ── 无商业闭环，纯蹭热点做 PPT   │
│ 3. 组织剧震与高流失 (Turnover Trap) ── 半年换三任主管，离职率爆表   │
│ 4. 虚假指标与背锅机制 (Metrics Trap)── 业务衰退让算法指标背锅      │
│ 5. 挂羊头卖狗肉 (Scutwork Trap)    ── 招架构师，实际做人工标注爬虫 │
└──────────────────────────────────────────────────────────────────┘
```

---

### 红旗 1：算力与基建欺诈 (Compute Trap)
- **现象特征**：JD 赫然写着“主导百亿/千亿参数大模型预训练与持续对齐”，但面试中对集群拓扑吞吐量闪烁其词。
- **真实陷阱**：团队实际只有几台 8 卡 4090 或租用不稳定的低价公有云 Spot 实例；经常因为云商断供导致几个月的训练中断；没有独占卡资源，甚至团队内部为了争夺一张卡要发邮件审批。
- **杀伤力**：★★★★★（直接摧毁技术成果产出，一年毫无有效产出）

### 红旗 2：伪 AI 与战略摇摆 (Strategy Trap)
- **现象特征**：公司核心主营业务与 AI 毫无关联（如传统代理记账、低端电商代运营），老板被行业宣讲会刺激后设立独立 AI Lab。
- **真实陷阱**：既无自有高质量行业数据，也无清晰商业转化链路。一旦资本市场降温或主营业务现金流吃紧，AI 部门是第一个被整体优化的对象。
- **杀伤力**：★★★★★（极高概率在入职 3-6 个月内遭遇团灭）

### 红旗 3：组织剧震与高流失率 (Turnover Trap)
- **现象特征**：该岗位长期挂在猎聘/脉脉等平台，HC 常年开放；或者同一个职位近期有 2-3 个猎头重复推荐。
- **真实陷阱**：上一任员工由于管理暴政、不合理的考核压力或资源被克扣而愤然离职；入职后你将直接接盘毫无交接文档的“屎山遗留代码”。
- **杀伤力**：★★★★☆（心理压力巨大，陷入无休止的技术救火）

### 红旗 4：虚假指标与背锅机制 (Metrics Trap)
- **现象特征**：考核指标脱离技术边界（如要求算法工程师背“日活用户增长 50%”或“次月留存率提高 20%”）。
- **真实陷阱**：业务基本盘本来就在下滑，产品设计和运营无能为力，将希望寄托在“大模型魔法”上；一旦业务未能反弹，算法组承担全部责任，绩效直接垫底打 C。
- **杀伤力**：★★★★☆（绩效被毁，影响后续背景调查）

### 红旗 5：挂羊头卖狗肉 (Scutwork Trap)
- **现象特征**：职位挂着“资深算法研究员 / 架构师”，工作内容却充斥着“收集行业竞品数据”、“整理清洗客服对话语料”。
- **真实陷阱**：团队缺少基础工程与数据支持，高薪把你招进来，80% 的时间被派去写爬虫、手写正则替换、做人工 Badcase 质检打标。
- **杀伤力**：★★★★☆（核心技术手艺迅速生疏，简历被废）

## 15 道黄金面试反问探针 (Golden Reverse-Interview Probing Questions)

> **使用原则**：在面试最后的“你有什么问题想问我吗”环节，挑选 2-3 个最具针对性的问题抛给面试官（HM 或 技术总监）。仔细观察对方回答时的**眼神、语速、是否有停顿、是否顾左右而言他**。

### 维度 A：探测硬件与算力真实底牌
1. **“请问团队目前独占并可支配的物理 GPU 规模与型号大概是多少？训练集群采用的网络拓扑与存储方案是怎样的？”**
   - *绿灯信号*：坦诚且自豪地报出卡数、网络协议（如“我们有 512 张 H800，自建 RoCE v2 无损网络，配合 GPFS 存储”）。
   - *红旗信号*：“我们在云上有充足资源 / 按照需求动态申请 / 这个涉及公司机密不能细说”。
2. **“我们在训练大规模任务时，出现节点硬件故障（如 ECC 错误、慢卡、断网）的频率如何？目前从故障触发到 Checkpoint 自动恢复通常耗时多久？”**
   - *绿灯信号*：讲出具体工程痛点和解决机制（如“已实现健康检查探针，分钟级自动剔除隔离慢节点并 resume”）。
   - *红旗信号*：“基本没怎么遇到过断卡 / 这个主要靠运维同学人工排查”。

### 维度 B：探测业务落地与商业真实现状
3. **“目前这套模型/系统，在公司内部服务的核心业务场景是什么？当前它所贡献的最具代表性的量化业务收益（如收入、降本比例）大概是什么量级？”**
   - *绿灯信号*：给出清晰的数据因果链条（如“支撑了内部 80% 的智能客服，替代了每年 1200 万的人力外包成本”）。
   - *红旗信号*：“目前主要是探索性质 / 内部各个组都在试用，还在看数据”。
4. **“在推进大模型落地的过程中，我们目前遇到的最大业务阻力或产品边界是什么？业务方最常抱怨的问题是延迟、成本还是生成幻觉？”**
   - *绿灯信号*：对落地真实痛苦有深刻共鸣，能清晰说出业务博弈与折中取舍。
   - *红旗信号*：“业务方挺满意的，我们技术很领先”。

### 维度 C：探测团队稳定性与考核真相
5. **“这个岗位设立的核心背景是什么？是业务高速增长带来的新增编制，还是替换已有成员的 Backfill 补缺？”**
   - *绿灯信号*：坦诚告知是业务线扩张，或者诚实说明前任的职能演进。
   - *红旗信号*：表情迟疑，闪烁其词，含糊说“正常人才梯队轮转”。
6. **“如果我非常有幸加入团队，在入职前 6 个月内，衡量我工作成败的最关键的 1-2 项核心交付物（Milestones）分别是什么？”**
   - *绿灯信号*：目标极度清晰具象（如“3 个月内把 Agent 工具调用准确率从 72% 提升到 85%，6 个月完成核心系统全量切换”）。
   - *红旗信号*：“先熟悉代码看文档，把技术底座打扎实，到时候看领导安排”。
7. **“团队在过去一年中，技术架构或技术路线发生过方向性调整吗？比如从自研转向开源底座，或者推翻过哪套自研方案？”**
   - *绿灯信号*：客观反思技术路线演进，认可技术变迁中的经验教训。
   - *红旗信号*：“我们一直在紧跟业界动态，几乎每个月都在快速调整”。

## 团队健康度评估打分卡 (Team Health Scorecard)

在面试结束后 15 分钟内，根据面试官给出的反馈完成打分（满分 100 分）：

| 评估维度 | 权重 | 满分判断标准 (20分) | 危险信号 (0-5分) | 本次得分 |
|---|:---:|---|---|:---:|
| **硬件与基建支撑** | 20% | 独占先进集群、全自动化容错与监控 | 蹭卡、审批困难、缺乏存储网络基建 | |
| **技术掌舵人水平** | 25% | HM 具有硬核一手技术背景，知行合一 | HM 不写代码、只看 PPT 汇报、迷信流行词 | |
| **商业闭环明确度** | 20% | 变现链路清晰，有强劲现金流支撑 | 纯靠外部融资或补贴，无真实付费客户 | |
| **团队流动稳定性** | 15% | 核心骨干稳定 2 年以上，HC 规划有序 | 频繁离职换人，一年流动率超 40% | |
| **工程质量与文化** | 20% | 重视 Code Review、CI/CD 与单元测试 | 屎山随意上线、线上救火常态化、推诿扯皮 | |

- **总分 ≥ 80 分**：优质团队，技术路线清晰，值得全力争取。
- **总分 60-79 分**：中规中矩，存在部分瑕疵，需在谈薪时争取溢价补偿。
- **总分 < 60 分**：**严重深坑，坚决 No-Go**，切莫贪图虚名或虚高薪资盲目接盘！
