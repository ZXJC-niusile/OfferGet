# JD 细粒度解码与要求-证据矩阵规范（JD Matrix Framework）

在技术招聘与高端技术岗位（尤其是大模型/分布式/高并发架构）求职中，简历的转化率取决于**候选人技术证据链与岗位真实需求的共振程度**。

绝大多数求职者直接根据 JD 表面的三五行字进行泛化包装，既容易踩中 HR 的招聘公关套话，又容易在初筛阶段因硬性门槛不符被系统秒拒。本规范确立了 **8 维细粒度 JD 解码体系**、**要求-证据矩阵结构**、**五态定性评估机制** 以及 **硬门槛独立物理隔离原则**。

## 一、 8 维细粒度 JD 解码规范

当面对一份原始 JD 时，必须将其解构为 8 个正交维度，严禁眉毛胡子一把抓：

```text
┌───────────────────────────────────────────────────────────────────┐
│                     原始招聘职位描述 (Raw Job Description)         │
└─────────────────────────────────┬─────────────────────────────────┘
                                  │
      ┌───────────────────────────┼───────────────────────────┐
      ▼                           ▼                           ▼
[1. 硬性门槛]                [2. 核心职责]                [3. 核心技能]
(学历/年限/资质)             (考核目标/日常产出)          (算法原理/工程深度)
      │                           │                           │
      ├───────────────────────────┼───────────────────────────┤
      ▼                           ▼                           ▼
[4. 业务场景]                [5. 工具平台]                [6. 行业背景]
(高并发/长文本/推荐)         (PyTorch/vLLM/K8s)           (电商/金融/自动驾驶)
      │                           │                           │
      └───────────────────────────┼───────────────────────────┘
                                  ▼
                     [7. 差异化加分项 (Bonus)]
                     (顶会第一作者/万星开源Committer)
                                  │
                                  ▼
                 [8. 公司招聘套话与公关黑话过滤]
                 (识别并过滤"抗压/狼性/拥抱变化"噪音)
```

### 1. 硬性门槛 (Hard Qualifications / Gates)
- **范畴**：学历层次（如 985/211/全日制统招硕博）、专业背景、法定最低工作年限、特定资格证书、强制合规许可。
- **属性**：绝对刚性，实行一票否决制。

### 2. 核心职责 (Core Responsibilities)
- **范畴**：入职后前 6 个月的主要考核产出（OKR/KPI），如“负责长上下文推理框架性能重构”、“负责千万级 DAU 召回链路稳定性保障”。
- **属性**：决定简历中项目经历的**第一锚点排布顺序**。

### 3. 核心技能 (Core Technical Competencies)
- **范畴**：该岗位不可替代的核心技术栈与底层工程内功。
- **示例**：CUDA 算子调优、分布式通信 Collective Communication、GRPO 强化学习、KV Cache 分页管理、MySQL Binlog 事务隔离。

### 4. 业务场景 (Business Scenarios / Domain Context)
- **范畴**：技术落地的具体业务复杂度与语境。
- **示例**：低时延超大并发（P99 < 50ms, QPS 10w+）、多模态实时交互、冷启动稀疏特征、端侧算力极致受限环境。

### 5. 工具、框架与基础设施 (Tools, Frameworks & Infra)
- **范畴**：生产环境已确立的选型。
- **示例**：PyTorch、Megatron-LM、DeepSpeed、vLLM、SGLang、Triton Inference Server、Docker、Kubernetes、Ray。

### 6. 行业背景 (Industry Background / Vertical Experience)
- **范畴**：特定行业的领域认知（Domain Knowledge）。
- **示例**：量化高频交易、广告计算与搜索推荐、自动驾驶感知规划、出海跨境电商、医疗合规。

### 7. 加分项 (Bonus Points / Differentiators)
- **范畴**：能从同质化候选人中迅速脱颖而出的杀手级资质。
- **示例**：NeurIPS/ICLR/ACL 顶会一作、知名开源项目 Core Maintainer、ACM-ICPC 区域赛金牌、Kaggle Grandmaster。

### 8. 公司招聘套话与公关黑话过滤 (Corporate Fluff & PR Noise Filtering)
- **原则**：直接剔除招聘文案中缺乏技术实体与量化评价的形容词，防止误导匹配。
- **常见黑话清单与过滤规则**：
  - “抗压能力强 / 具备敬业精神” $\to$ `[噪音：暗示高强度加班，不计入技术匹配]`
  - “拥有自我驱动力 / 拥抱变化” $\to$ `[噪音：暗示业务方向常变或需求不确定]`
  - “具有跨团队闭环赋能思维” $\to$ `[套话：翻译为具备基础沟通协作能力]`
  - “热爱前沿技术，对新技术有狂热探索精神” $\to$ `[套话：不设实际门槛的修饰语]`

## 二、 要求-证据矩阵 (Requirement-Evidence Matrix)

在生成或重构简历前，必须构建要求-证据矩阵，将 JD 拆解项与候选人的原子事实台账进行逐项映射：

| 维度编号 | JD 细粒度要求描述 | 技术关键词提取 | 候选人对应凭证 (原子 Claim ID) | 五态定性评估 | 匹配度 (0-100) | 针对性重构与弥补策略 |
|:---:|:---|:---|:---|:---:|:---:|:---|
| **D1-GATE** | 计算机或相关专业统招硕士及以上 | 硕士, 计算机/软件 | CLM-00-EDU (985 软件工程硕士) | **已匹配** | 100 | 首屏顶部直接标明，通过 ATS 硬筛。 |
| **D2-RESP** | 负责大模型在线推理加速与长文本落地 | 推理加速, 长上下文, 线上落地 | CLM-01-METH, CLM-01-METR | **已匹配** | 95 | 提炼为第一核心项目，强化 P99 -40% 效果。 |
| **D3-SKILL**| 精通 TensorRT-LLM 或 vLLM 核心机制 | vLLM, PagedAttention, Kernel | 仅在项目中提过“使用 vLLM 部署” | **证据不足** | 50 | 追问源码级调优细节，补充 Chunked-Prefill 调优证据。 |
| **D4-SCENE**| 具备日请求量千万级的高并发业务经验 | 高并发, 千万QPS, 容灾隔离 | 候选人经历多为单机/离线评测实验室环境 | **真实缺口** | 20 | **严禁造假**。以可迁移的“单机高并发压力测试与极端负载恢复能力”补位，做好面试防御。 |
| **D5-TOOL** | 熟练使用 Ray 进行分布式资源调度与部署 | Ray, Ray Train, Ray Core | CLM-05-TOOL (有使用经验但未写明) | **表达缺口** | 60 | 将 Ray 调度机制与集群节点管理明确写入技术链路。 |
| **D7-BONUS**| 在 GitHub 有高星开源项目贡献者优先 | 开源贡献, Committer, PR | CLM-06-OSS (合并 8 个核心功能 PR) | **已匹配** | 100 | 将 GitHub 仓库与 PR 链接压入 Headline 首屏。 |

## 三、 五态定性评估标准

每一个 JD 要求与候选人经历的比对，必须严格定性为以下 5 种状态之一，禁止使用模糊的“还行”、“较为符合”：

```text
┌─────────────────────────────────────────────────────────────┐
│                   五态定性评估状态划分                        │
├─────────────────────────────────────────────────────────────┤
│ 1. 已匹配 (Matched)        ──> 强证据闭环，直接作为核心卖点    │
│ 2. 表达缺口 (Expression Gap) ──> 做过但未写出，改写术语前置曝光 │
│ 3. 证据不足 (Weak Evidence) ──> 仅有声称无参数，追问挖掘量化细节│
│ 4. 真实缺口 (Real Gap)      ──> 确实未做过，诚实认清+迁移能力补位│
│ 5. 待确认 (To Be Confirmed)  ──> 素材模糊，需向候选人当面核对    │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 `已匹配 (Matched)`
- **定义**：候选人具备 Level A/B 级强证据，技术栈、量化指标与项目落地完全满足或超越 JD 描述。
- **交付策略**：提炼为高势能 Mini-RFC 叙述，放在简历最醒目位置，施加参数级威慑。

### 3.2 `表达缺口 (Expression Gap)`
- **定义**：候选人实际深入做过该项工作，但在当前简历中**由于用词不规范、表述过于谦逊简略、或使用了非业界通用黑话**，导致 ATS 机筛和 HR 无法识别。
- **交付策略**：对照 `references/ai-agent-lexicon.md` 与行业标准术语，精准重写，前置暴露核心词汇。

### 3.3 `证据不足 (Insufficient Evidence)`
- **定义**：候选人声称具备该技能，但经历中缺乏具象技术参数、对比基线、量化指标或落地形态。
- **交付策略**：启动穿透式挖料，若无法补充客观事实，主动降级角色词（如“负责”降为“参与”），避免面试反噬。

### 3.4 `真实缺口 (Real Gap)`
- **定义**：经过穿透式盘点，候选人确实没有任何相关实践或知识储备。
- **防伪铁律**：**绝对严禁无中生有编造经历！**
- **应对策略**：
  1. **坦诚防御**：在面试问答防御卡中做好“该方向我尚未在生产环境实操，但我深入研读过其开源实现...”的坦诚话术；
  2. **可迁移能力补位**：用相关底层能力（如虽未实操过 Triton 算子，但具备深厚 CUDA C 编程功底）进行侧面支撑。

### 3.5 `待确认 (To Be Confirmed / TBC)`
- **定义**：候选人提供的素材存在口径矛盾、时态含糊或范围不明。
- **交付策略**：在成稿中标记 `<span class="todo">待确认：xxx</span>`，未消除前禁止交付最终 PDF。

## 四、 硬门槛独立物理隔离原则 (Hard Gate Physical Isolation)

在求职评估中，**最致命的错误是将硬门槛与软技能进行加权平均**（例如：“虽然学历不符，但技术非常强，综合打分 85 分”）。

> **硬门槛物理隔离铁律**：
> 1. **独立门禁判定**：学历、工作年限、强制行业资格等硬性门槛必须作为**一级独立物理隔离层（Hard Gate 0/1 Pass/Fail）**；
> 2. **严禁分数对冲**：技术评分再高（哪怕 100 分），若 Hard Gate 为 0（不通过），整体结果就是 0；
> 3. **破局机制独立化**：当发现硬门槛不满足时，系统必须立即向候选人报警，并触发**非常规破局通道**，而不是用虚假的“高综合分”误导候选人去送死。

### 硬门槛不达标时的三大破解通道：
1. **通道 A：业务直聊 / 部门负责人直推**：
   - 绕过大厂 HR 共享服务中心（SSC）与 ATS 简历库系统，直接通过脉脉/Boss 直聘精准触达业务部门架构师或技术 Leader；
   - 触发工具：配合 `references/hr-pitch-guide.md` 中的黄金三段式话术。
2. **通道 B：标杆开源背书特批**：
   - 拥有顶级开源项目 Maintainer 身份或顶会论文，推动用人部门申请“特殊人才硬门槛豁免审批”。
3. **通道 C：技术外包/生态伙伴转正跳板**：
   - 先以生态合作方或外协架构顾问切入，在业务中证明实力后再转正内部编制。

## 五、 大模型 / 算法架构实战解码示例

### 原始 JD 样本：
> **岗位名称**：大模型推理优化资深工程师 / 专家  
> **职责要求**：  
> 1. 统招硕士及以上学历，计算机相关专业，3 年以上大模型或高性能计算经验；  
> 2. 负责百亿/千亿大模型在线推理系统的架构设计与性能优化，保障极端业务流量下的稳定性；  
> 3. 深入理解主流开源推理引擎（如 vLLM / TensorRT-LLM / SGLang），精通 PagedAttention、Continuous Batching 等底层原理；  
> 4. 具备强烈的团队合作精神，具备抗压能力，拥抱业务变化与挑战；  
> 5. 加分项：有知名开源项目贡献经历，或在 ML/System 顶会发表过论文者优先。

  - "百亿/千亿大模型在线推理系统架构设计"
